# 글쓰기 언어 필터

`frontend/lib/profanity-policy.json`이 브라우저와 서버의 공통 정책이다. Gradle은 이 파일을 서버 classpath와 실행 jar에 포함한다. Docker 빌드 컨텍스트도 이를 포함하도록 저장소 루트를 사용한다.

NFKC 정규화 후 금지 표현, 반복 음절, 음절 사이 공백·문장부호·기호·보이지 않는 문자를 검사한다. 단어 경계와 한국어 조사·어미를 고려하여 `시발점`, `졸라매고`, `등신대` 같은 부분 일치를 허용한다. 동물의 새끼를 설명하는 일부 표현과, 인용 바로 뒤에 뜻이나 사용 금지를 설명하는 교육적 구문을 예외로 둔다. 예외 뒤의 나머지 문장도 계속 검사한다. 규칙 방식이므로 모든 신조어나 복잡한 문맥을 판별하지는 못한다.

## 결합 표현 누락 수정

### `ㅅㄲ` 초성 표현 추가 (2026-10-28)

공통 정책의 `initialTerms`에 `ㅅㄲ`를 추가했다. 기존 자음 접두사 및 조사·어미 규칙을 그대로 사용하므로 `ㄱㅅㄲ`, `ㅈㅅㄲ`, `ㅋㅋㅅㄲ`, `ㄱㄴㄷㅅㄲ`, `ㅅㄲ야`, `ㅅㄲ네`도 감지한다. 각 예시에 대해 양쪽 필터와 프론트 경고·단서 찾기 차단·수정 후 재분석, 직접 API의 422 응답·분석기 및 저장소 미호출을 검증한다. 자동 생성한 모든 기본·쌍자음 및 순서쌍 접두사를 `ㅅㄲ`, `ㅅㄲ야`, `ㅅㄲ네`에도 적용한다. `자음 ㅅ과 ㄲ을 배웠다.`, `사과를 깨끗하게 씻었다.`를 정상 문장 사례로 추가했다.

추가 후 프론트 테스트 93개, 서버 글쓰기 테스트 13개 및 TypeScript 검사가 통과했다. 기존 Gemini 결과 처리와 복습 저장·완료 회귀 테스트를 포함하며 실제 외부 AI는 호출하지 않는다.

### 단독 자음 접두 우회 수정 (2026-10-28)

왼쪽 경계의 `\p{L}`에는 단독 한글 자음도 포함된다. NFKC 정규화는 `ㄱ` 등을 조합용 자모로 바꾸지만 문자 속성은 그대로이므로, 기존 경계는 `ㄱ병신`의 `병신` 앞에서 실패했다. 특정 접두어 목록을 늘리는 대신 공통 정책의 `consonantPrefix` 문자 범위를 양쪽 필터에 적용했다. 왼쪽 경계 뒤에서 단독 자음 0개 이상과 기존 접두·금지어 규칙을 순서대로 소비한다. 기본·쌍자음, 겹자음 및 NFKC 조합용 자모를 처리하며, 완성형 한글과 숫자의 경계 및 오른쪽 조사·어미 규칙은 유지한다. `씹새`를 완성형 금지어에 추가했다.

기본·쌍자음 19개와 모든 순서쌍 361개, 3개 이상 연속 자음 및 겹자음으로 접두사 383개를 자동 생성한다. 양쪽에서 각각 금지어·초성·혼합 표현 35,619건과 정상 표현 2,304건을 검증한다. 정상 표현에는 `시발점`, `등신대`, `졸라매고`, `씹새우를 관찰했다.` 등이 포함된다. 직접 API 테스트는 생성한 접두사와 `병신`의 조합 및 대표 표현에 대해 422 응답과 분석기·저장소 미호출을 확인한다. 프론트 테스트는 요청한 여섯 예시에 대해 경고, 버튼·핸들러 차단, 원문 유지, 수정 후 분석 재개를 확인한다.

이번 검증 결과는 프론트 테스트 77개, 서버 글쓰기 테스트 13개, TypeScript 검사 모두 통과다. 서버의 기존 Gemini 결과 처리와 H2 복습 저장·완료 테스트를 포함한다. 실제 Gemini API는 호출하지 않았다. Windows 한글 경로의 Gradle 테스트 클래스 로딩 문제를 피하기 위해 임시 영문 빌드 경로를 사용하고 Byte Buddy 에이전트를 시작 시 로드했다. 전체 서버 테스트와 프로덕션 빌드는 이번에 실행하지 않았다. 아래 검증 수치는 이전 작업 기록이다.

기존 양쪽 구현은 `(?<![\p{L}\p{N}])금지어+접미규칙(?![\p{L}\p{N}])` 구조였다. 정확 일치만 검사하는 것은 아니었지만, 왼쪽 경계가 `게병신`의 `병신` 앞 글자를 거부하고, 기존 접미 규칙에 `같네`가 없어 `좆같네`의 오른쪽 경계가 실패했다. `ㅈ`과 완성형이 섞인 표현에 대한 별도 규칙도 없었다. 기존 공백·기호 허용은 금지어 내부에 한정되어 있었다. 프론트와 서버의 기준 차이로 생긴 누락은 아니었다.

개선한 규칙은 완성형 목록(`terms`), 초성 약어(`initialTerms`), 단독으로는 모호한 초성 어근(`mixedRoots`)을 구분한다. `ㅅㅂ`, `ㅂㅅ`은 단독으로도 차단하지만 `ㅈ`은 혼자 있을 때 허용하고 `같네`, `같아요` 등 서술형 결합이 있어야 차단한다. 공통 정책의 접두 표현(`prefixes`), 조사·어미(`suffix`), 서술형(`predicateSuffix`)을 조합한다. 경계를 없애거나 임의의 한글 접사를 모두 허용하지 않는다. 음절 반복뿐 아니라 `병 병 신`, `ㅅ ㅅ ㅂ`처럼 반복 사이의 공백·기호도 처리한다.

공통 테스트 데이터의 `blockedExpressions`, `allowedExpressions`는 각각 단독, 문장 중간, 문장 끝의 세 위치에서 양쪽 구현에 적용한다. 직접 API 호출은 필수 차단 표현 7개 × 위치 3개를 검증하고, 프론트의 경고·원문 유지·실행 차단·수정 후 재분석도 필수 7개 표현에 각각 적용한다. 교육적 설명의 허용과 실제 인용 공격의 차단을 구분해 검사한다.

이번 수정의 실제 결과: 프론트 테스트 69개, 서버 글쓰기 테스트 11개 및 TypeScript 검사 통과. 서버 테스트는 정상 분석·복습 저장 회귀 검증을 포함한다. Mockito의 동적 에이전트 연결이 환경에서 실패하여, 추적되지 않는 임시 Gradle init script에서 Byte Buddy 에이전트를 JVM 시작 시 로드한 뒤 통과했다. 이번 수정에서는 전체 백엔드 테스트와 프로덕션 빌드를 다시 실행하지 않았다. 아래 전체 테스트 실패·빌드 결과는 이전 구현 작업의 결과이다.

브라우저는 입력 즉시 입력창 아래에 지정된 제목과 내용을 표시하고 버튼과 실행 핸들러를 모두 차단한다. 입력을 지우지 않으며 수정하면 경고와 차단을 해제한다. 손글씨 인식 결과도 같은 검사를 받는다.

서버는 학생 소유권 확인 후, Gemini 등 분석기 호출 및 엔티티 생성·저장 전에 검증한다. 감지 시 HTTP 422와 사용자 메시지를 반환한다. 외부 API를 사용하지 않으므로 AI 장애와 무관하게 검사한다. 정상 글의 분석·저장·복습 흐름은 유지한다.

## 실행

Java 21과 기존 `.env` 설정을 사용한다. 루트에서 별도 터미널로 실행한다.

```powershell
npm.cmd run backend
npm.cmd run dev
```

웹 주소: http://localhost:3000 . Docker는 루트에서 `docker compose up --build`로 실행한다. 기존 `.env`를 덮어쓰지 않는다.

## 검증 명령

```powershell
node --test frontend/tests/writing-flow.test.cjs
node node_modules/typescript/bin/tsc --noEmit -p frontend/tsconfig.json
npm.cmd run build --workspace frontend -- --webpack
cd backend
.\gradlew.bat test --tests 'kr.co.hanguldetective.writing.*'
```

공통 정책 사례는 양쪽 테스트에서 동일하게 읽는다. 프론트 테스트는 원문 유지, 경고, 실행 차단, 수정 후 재분석, 기존 분석·복습을 검증한다. 서버 테스트는 MockMvc 직접 요청의 422 응답, AI 장애를 가정해도 분석기·저장소 미호출, 정상 분석 및 H2 메모리 DB의 복습 저장·조회·완료를 검증한다. 실제 Gemini나 Supabase를 호출하지 않는다.

현재 Windows 환경에서는 한글 경로 때문에 Gradle 테스트 워커가 클래스를 찾지 못했다. 기존 영문 캐시 `C:\GradleCache`와 임시 영문 빌드 경로로 우회하여 검증했다. 기본 Turbopack 빌드는 프로세스 오류가 발생했고 Webpack 빌드는 통과했다. 전체 백엔드 테스트에서는 글쓰기와 무관한 `AccountControllerTest.deletionRemovesAllDependentRecordsAndPreservesOtherAccountsAndSharedQuestions`가 `TransientObjectException`으로 실패했다. 계정 기능은 수정하지 않았다.
