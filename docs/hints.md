# 단계별 힌트

받아쓰기, 객관식 문제, 오답 복습, 자유 글 다시 쓰기에 같은 3단계 UI를 사용한다. 힌트 생성에는 Gemini나 다른 외부 모델을 호출하지 않는다.

1. 생각할 단서: 오류 유형별 학습 방향. 받아쓰기는 저장된 낱말 설명에 정답이 포함되지 않았을 때 그 설명을 사용한다.
2. 글자 단서: 한글을 NFC로 정규화한 뒤 글자 수와 초성을 표시한다. 띄어쓰기 위치를 유지한다.
3. 보기 비교: 정답을 포함한 보기를 표시하되 자동 선택·채점하지 않는다. 받아쓰기의 다른 보기는 DB에 저장된 받아쓰기 정답에서 가져오며 새 낱말을 생성하지 않는다. 다시 쓰기는 원래 표현과 교정 후보를 비교한다.

## API

- `POST /api/questions/{id}/hint`: `{ studentId, level: 1..3 }`
- `POST /api/question-reviews/{id}/hint`: `{ level: 1..3 }`
- 기존 `POST /api/writing-errors/{id}/hint`: 저장된 힌트 단계를 다음 단계로 올리며 3단계에서 유지한다.

응답은 `{ level, hint, choices }`다. 1·2단계에는 choices가 비어 있다. 문제 힌트는 학생 소유권을, 복습·글 힌트는 해당 기록의 학생 소유권을 검증한다.

문제·오답 복습 힌트는 화면에서 현재 단계를 유지하고, 페이지 새로고침 시 처음부터 볼 수 있다. 자유 글 힌트 사용 단계는 기존 writing_errors.hint_level_used에 저장된다. 미해결 글의 초기 응답에는 정답·상세 설명·저장된 AI 힌트·선택지를 보내지 않는다. 정답을 맞힌 뒤에는 정답·설명을 조회할 수 있다.

힌트는 이미 저장된 정답·오류 후보를 설명하는 보조 기능이다. 오류 후보 자체가 올바른지를 판정하는 맞춤법 검사기는 이번 작업에서 변경하지 않았다. 손글씨 인식 및 외부 API 설정도 변경하지 않았다.
